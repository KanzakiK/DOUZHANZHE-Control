# 2026-11-02

## 壁纸自动轮换「看不见」根因诊断（已确认）

- 用户现象：斗战者控制台 UI 背景（非 Windows 桌面壁纸）在托盘区不打开窗口时不轮换。
- 结论：轮换服务**在后端**（`server/api/BackgroundRotationService.cs`，`BackgroundService` 托管进 API 进程，跟着 `Douzhanzhe.API.exe` 独立进程跑，不依赖 Shell 窗口）。用户原以为服务放错到 Shell，是误判。
- 真因：后端只把 `config/background.*` 文件换掉（仅 `source=="network"` 模式会轮换；`local` 单张固定图不轮换），但**前端只在挂载时读一次 `/api/background`**（`App.jsx:66` / `SettingsPanel.jsx:97`），写进 CSS 变量 `--wallpaper-image`，无定时轮询、无 WebSocket 推送、无缓存戳。磁盘图已换，屏幕上看不见。页面重载（重启/后端恢复 Reload/F5）才会重新拉，故"开窗口好像轮换、托盘像冻死"。
- 用户当前模式：网络轮换。属"轮换了但看不见"。
- 修复方向（待用户拍板机制）：后端轮换时往 `background-opts.json` 写 `lastRotated` 时间戳；前端定时（~30s）轮询 `/api/background-opts`，`lastRotated` 变了就用 `/api/background?t=<戳>` 重新 `applyWallpaperCss`。`/api/background` 已 `no-store`，保证拿到新字节。隐藏窗口下 WebView2 JS 仍运行，轮询在托盘态也生效。
- 待定：用户倾向轮询还是 WebSocket 推送（推送仍需重连时 reconcile，本质仍要轮询兜底）。
