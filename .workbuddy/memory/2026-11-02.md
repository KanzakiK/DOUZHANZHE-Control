## 壁纸自动轮换「看不见」根因诊断（已确认）

- 用户现象：斗战者控制台 UI 背景（非 Windows 桌面壁纸）在托盘区不打开窗口时不轮换。
- 结论：轮换服务**在后端**（`server/api/BackgroundRotationService.cs`，`BackgroundService` 托管进 API 进程，跟着 `Douzhanzhe.API.exe` 独立进程跑，不依赖 Shell 窗口）。用户原以为服务放错到 Shell，是误判。
- 真因：后端只把 `config/background.*` 文件换掉（仅 `source=="network"` 模式会轮换；`local` 单张固定图不轮换），但**前端只在挂载时读一次 `/api/background`**（`App.jsx:66` / `SettingsPanel.jsx:97`），写进 CSS 变量 `--wallpaper-image`，无定时轮询、无 WebSocket 推送、无缓存戳。磁盘图已换，屏幕上看不见。页面重载（重启/后端恢复 Reload/F5）才会重新拉，故"开窗口好像轮换、托盘像冻死"。
- 用户当前模式：网络轮换。属"轮换了但看不见"。
- 修复方向（待用户拍板机制）：后端轮换时往 `background-opts.json` 写 `lastRotated` 时间戳；前端定时（~30s）轮询 `/api/background-opts`，`lastRotated` 变了就用 `/api/background?t=<戳>` 重新 `applyWallpaperCss`。`/api/background` 已 `no-store`，保证拿到新字节。隐藏窗口下 WebView2 JS 仍运行，轮询在托盘态也生效。
- 决议（用户拍板）：**塞进遥测 WS 帧**（零新增流量、延迟≤250ms、托盘态生效），不用独立轮询。
- 已落地并提交（本地 baea254，未推送）：
  - 后端 `BackgroundRotationService` 加 `static DateTime? LastRotatedUtc`，轮换成功时写；
  - `TelemetryBackgroundService` 在 250ms 遥测帧加 `bgLastRotated`（Unix 秒）；
  - `Program.cs` `/api/background-opts` GET 返回 `lastRotated` 兜底；
  - 前端 `uxtuAdapter.refreshWallpaperOnRotate(stamp)` 按戳带 `?t=` 重新套用；
  - `useControlState` 遥测 onData 检测戳变化触发刷新。
- 验证：前端 `npm run build` 通过；后端 `dotnet build -c Release` 0 警告 0 错误。手动提交避免 AfterBuild 钩子生成泛化 message；未 push。
- 附带彩蛋：手动「立刻切换」也走 RotateOnceAsync → 同样置戳 → 前端即时刷新（无需重载）。

## 启动慢 + 前端误报"后端未连接" 的根因定位（2026-11-02 15:40-15:55）

- 用户实测 pre.2 反馈：启动黑屏一阵、前端渲染后仍显示"后端未连接"、要等好一会儿才自愈、比旧版慢；并质疑默认配置名显示成 `cfg-office`（切换配置才正常）。
- **根因 1（启动慢，真凶在 API 侧）**：`ProcessMonitorService` 构造函数里**同步**建立两个 WMI 事件订阅。实测本机 `ManagementEventWatcher.Start()`：`__InstanceCreationEvent` **9.4s**、`__InstanceDeletionEvent` **10.4s**（WMI 需先做进程基线枚举）。该服务在 `Program.cs:195` 顶层 `app.Run()` 之前被解析 → **端口 3100 要等 ~20s 才监听**。日志佐证：`[GameProfile] Loaded 4 profiles` → `[ProcessMonitor] WMI event subscriptions created` 之间 **17.16s** 空档。
  - 连带效应：Shell 就绪检测干等 → 黑屏 ~18s；前端恰好在后端仍在启动时加载 → `/api/telemetry` 与遥测首帧延迟 → `backendOnline` 为 false → 误报"后端未连接"。
  - 修复：WMI 订阅改后台线程建立（`Task.Run`），端口立即可用；顺带把 watcher 字段的建立/销毁加锁 + `_disposed` 检查，避免与 Dispose 竞态泄漏。
- **根因 2（前端误报）**：`useControlState.js` 的 `backendOnline` 初值是 `false` → 前端一加载 1.5s（`useStall(!backendOnline, 1500)`）后**必定**弹"后端服务未连接"，哪怕后端正常。改三态（null 未知 / true 在线 / false 明确离线），离线卡片仅在 `=== false` 时显示；模拟数据兜底也仅在明确离线时启用（未知态显示骨架而非假数据）；侧栏状态点加"连接中"。
- **根因 3（配置名）**：`ConfigBar.jsx:23` `currentProfile?.name || settings.mode` 在配置列表未加载时回退到内部 id → 显示 `cfg-office`。改为按 id 推导（剥 `cfg-` 前缀 → MODE_LABELS），用户自建配置仍显示自身名称。
- **诊断增强**：API 侧记录"进程启动 → 端口已监听"耗时；Shell 侧记录 WebView2 初始化耗时 / 后端就绪耗时 / Form1_Load 总耗时。
- 回归：`dotnet build -c Release`（API 强制全量重建 0 警告 0 错误；Shell 0 错误，仅既有 MSB3277 + CS8600@WndProc）、`npm run build` 通过、`npx vitest run` **17/17 通过**。
- 提交：AfterBuild 钩子自动提交并推送了代码（d7f7250 api/shell + ab5f836 chore + 0987c4a frontend，泛化 message）；CHANGELOG/package 版本号与本条日志另行手工提交（描述性 message）。版本 → 2.0.2-pre.3。
